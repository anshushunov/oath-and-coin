## Контекст

Закрывает `BQ-001` — первый блокирующий вопрос Gate 0 (`MVP_PLAN` §4.1). `TDD` §2.3 требует, чтобы симуляция запускалась без графического движка, а §4.1 — чтобы core не импортировал движок. `AGENTS.md` §2 запрещает агенту менять движок и язык без отдельного решения, поэтому запись нужна до первой строки игрового кода.

Две боли, названные владельцем продукта, — гранулярность артефактов и слепота агента к рантайму — не являются свойствами Godot: первая следует из организации проекта, вторая из отсутствия правила при наличии инструмента. Выбор стека влияет только на цену их лечения.

## Решение

- **Движок:** Godot 4, точный пин `Godot.NET.Sdk/4.7.1`. Диапазон «4.7.x» пином не считается: смешение API внутри минорной линии остаётся возможным.
- **Язык:** C# 12, `TargetFramework net8.0`. GDScript не используется, два языка не смешиваются.
- **Версия .NET SDK** пинуется `global.json` с `rollForward: disable` и `allowPrerelease: false`, чтобы patch-версия не менялась молча.
- Godot-проект (`game/`) в Gate 0 не создаётся: гейт не пишет ни строчки кода представления, а каталог заводится вместе с первым артефактом.

## Альтернативы

- **GDScript** — отклонено: он не существует вне Godot, поэтому `TDD` §2.3 и §4.1 выполнить физически нельзя, а `AGENTS.md` §10 («несовместимость подсистем ловит компилятор») со скриптовым языком превращается из механизма в декларацию.
- **Смешанный C# + GDScript** — отклонено: удваивает контекст агента и создаёт границу, на которой он будет ошибаться.
- **Диапазон версий движка вместо точного пина** — отклонено: смешение API 4.6/4.7 — типовая ошибка агентов на Godot, а воспроизводимость сборки требует одного значения.

## Последствия

- `simulation/` — обычная .NET-библиотека; её тесты гоняются `dotnet test` без бинаря Godot. В Dungeon Fortress ровно эта конструкция дала headless-прогоны, которые агенты использовали 3515 раз.
- Совместимость не предполагается, а подтверждена: `src/DungeonFortress.Game/DungeonFortress.Game.csproj` уже использует `Godot.NET.Sdk/4.7.1` с `net8.0` и собирается на этой машине, поэтому отдельный compatibility spike не нужен.
- Медленный тестовый контур (`gdUnit4`, runtime harness) появляется перед Milestone 1 отдельным планом, а не здесь.
- Обновление движка или SDK — ломающее изменение воспроизводимости и требует новой записи, а не правки этой.

## Проверка

Реализация: `global.json`, `Directory.Build.props`, `OathAndCoin.sln`.

Тест, который сломается при отмене решения: сборка на пине — `dotnet build OathAndCoin.sln -c Release` при SDK, отличном от `8.0.424`, падает из-за `rollForward: disable`. Границу «core собирается без движка» держит `tests/OathAndCoin.Simulation.Tests/CoreBoundaryTests.cs` (`SimulationProjectOutputs_ContainNoEngineArtifacts`).

Пересмотр — при выходе LTS-линии Godot, несовместимой с `net8.0`, или если harness перед M1 покажет, что `4.7.1` не держит headless-прогон.
