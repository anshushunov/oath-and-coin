# ADR-005 — Стабильные namespaced идентификаторы

> Дата: 2026-08-13
>
> Статус: accepted (решение владельца по Gate 0, 2026-08-13)

## Контекст

`TDD` §5.1 требует стабильных идентификаторов, независимых от отображаемых имён, `AGENTS.md` §6 — стабильных ID у контента, а §2 запрещает менять их схему без плана миграции. Схема идентификаторов входит в блокирующий блок Gate 0 (`MVP_PLAN` §4.1) именно поэтому: после того как ID попадут в сохранения и в контент, их формат становится дорогим в изменении.

Второй вопрос, который приходится решать вместе с первым: не всё, что похоже на идентификатор, является контентом. Коды причин в causal trace — закрытый словарь движка, а не сущность, которую кто-то заводит файлом.

## Решение

- **`ContentId`** — форма `namespace:name`, оба сегмента по `^[a-z][a-z0-9_]*$`. Сравнение и хеширование — ordinal, локаль машины не участвует.
- **Невалидное значение не может существовать:** конструктор приватный, единственные входы — `Parse` и `TryParse`. `default(ContentId)` считается неинициализированным и бросает при обращении, а не притворяется пустым идентификатором.
- **JSON-конвертер поставляется вместе с типом**, включая вариант для ключей словаря. Без этого `System.Text.Json` записал бы структуру как объект и прочитал бы её обратно как `default` без единой ошибки — гарантия «невалидного не бывает» осталась бы только на этапе компиляции.
- **`HeroId`** — runtime-идентификатор, целое число. Присваивается детерминированно, в порядке `ContentId` определений героев, а не в порядке файлов в каталоге.
- **Граница между двумя видами идентификаторов:** контент-адресуемые сущности получают `ContentId` (включая действия решения — `action:accept`, `action:decline`, которые при этом никогда не определяются файлом контента); закрытый словарь движка — коды причин `hero.decision.*` — остаётся точечными строками.
- **Ссылки на ресурсы идут по идентификатору**, а не по имени файла: портрет героя адресуется его `ContentId`.

## Альтернативы

- **Отображаемое имя как ключ** — отклонено: имена локализуются и правятся, а ключ должен переживать и то, и другое.
- **GUID** — отклонено: не читается в дифе, не пишется рукой в контенте и превращает конфликт слияния в загадку.
- **Плоский идентификатор без пространства имён** — отклонено: моддинг и будущие наборы контента столкнутся именами, а обнаружится это только при загрузке.
- **`HeroId`, назначаемый в порядке чтения файлов** — отклонено: порядок файловой системы не воспроизводим между машинами, и начальное состояние перестало бы быть функцией контента и seed.

## Последствия

- Дубликат идентификатора отвергается загрузчиком с указанием обоих файлов, а не выигрывается последним прочитанным.
- Известное ограничение, зафиксированное намеренно: `HeroId` в роли ключа JSON-словаря сейчас бросает исключение с внятным текстом. Для Gate 0 это неважно — состояние не сохраняется; при первой попытке сохранить падение произойдёт сразу, а не через месяц. Это вход в решение по сохранениям, а не пропуск.
- Изменение формата `ContentId` после появления сохранений требует плана миграции (`AGENTS.md` §2), то есть новой записи.
