# ADR-010 — Полный переход на TypeScript web stack с Electron-хостом

> Дата: 2026-08-16
>
> Статус: accepted (решение владельца, 2026-08-16)

## Контекст

`ADR-001` выбрал Godot 4.7.1 + C# на net8.0 как движок и язык Gate 0 и прямо заявил: две названные владельцем боли — гранулярность артефактов и слепота агента к рантайму — не являются свойствами Godot, а выбор стека влияет **только на цену их лечения**. Эта запись не спорит с той оценкой. Она добавляет к ней недостающую половину: цену измерили.

Измерение дал `ADR-008` и работа PR #9. Чтобы доказать, что информационный экран показывает то, что должен, потребовался собственный runtime harness: запуск отдельного процесса движка, разбор его терминального события, независимое построение ожидаемой модели, сверка трёх хешей, измерение layout, снятие кадра и сборка отчёта. На baseline это 1082 code line при потолке 1100, тогда как вся симуляция — 1045 (`bash ./scripts/code-lines.sh tools/OathAndCoin.Harness simulation` даёт оба числа по одному правилу). Инструмент, доказывающий наблюдаемость одного экрана, крупнее всех правил игры вместе взятых. PR #9 показал и границы этой конструкции: семантически неверный выбор причин прошёл множество внутренних проверок, зелёные хеши не обнаружили нулевой размер корня сцены, читаемость и достижимость содержимого потребовали отдельного layout measurement.

Одновременно продукт окончательно подтвердил свою форму. `DEC-007` зафиксировал UI-first презентацию и схематичный бой до валидации MVP, `DEC-004` и `DEC-006` — что причины решения являются частью интерфейса, `DEC-010` и `ADR-009` — что ядро игры это детерминированные переходы состояния с причинным следом. Ни одна из этих систем не нуждается в Godot runtime, а информационный UI в HTML/CSS строится прямо, а не через построенное кодом дерево `Control`.

Владелец продукта оптимизирует **скорость и надёжность агентской разработки**. Это и есть основание записи: не «Godot плох», а «цена наблюдаемости в выбранном стеке измерена и признана слишком высокой для этого продукта».

`AGENTS.md` §2 запрещает агенту менять движок, язык и платформы без отдельного решения, а §5 требует запись, когда изменение затрагивает несколько подсистем, дорого отменяется и меняет архитектурную границу. Здесь выполнены все три основания сразу.

## Решение

### Целевой стек — TypeScript целиком, C# в финальной архитектуре не остаётся

Весь production-код игры пишется на TypeScript: симуляция, application layer, контент-загрузчики, presentation models, UI, scenario runner, Electron main/preload и все автоматические тесты. Стек:

> TypeScript + React + PixiJS + Vite + Vitest + Playwright + Zod + Electron

C#, Godot, `.sln`, `.csproj`, `global.json`, пин Godot SDK и Godot-aware harness удаляются из production tree после достижения parity. C# **не** сохраняется как скрытый backend, sidecar-процесс или второй источник правды.

TypeScript 6.0.3 остаётся каноническим компилятором на всё время миграции. TypeScript 7 не используется: на 2026-08-16 у него нет стабильного programmatic API, из-за чего `typescript-eslint` и генерация деклараций не работают, а миграция осталась бы без статического анализа за пределами типов на все 29–44 focused work days. Переход на 7.x — отдельная задача после cutover и после выхода версии с совместимым lint/declaration tooling.

### Браузерное приложение является игрой; Electron только предоставляет desktop capabilities

Это главный архитектурный принцип записи, и из него следует всё остальное:

- **Renderer** — обычное браузерное приложение, ровно то же самое, что работает в Chromium без Electron.
- **Main process** — окно, файловая система, атомарные сохранения, логи, crash artifacts, Steamworks.
- **Preload** — узкий типизированный API через `contextBridge`, единственная поверхность, которую видит renderer.

Electron main не содержит игровых правил. Симуляция не знает о React, PixiJS, DOM, файловой системе, часах, Electron и Steam.

Браузерная сборка остаётся first-class target: разработка, CI, быстрые плейтесты и основная часть E2E идут в ней.

### Структура пакетов

Дерево фиксируется в этой записи ровно в том виде, в котором его строит план миграции:

```text
apps/web            # Vite entry, React composition, browser build
apps/desktop        # Electron main, preload, packaging, Steam adapter
packages/simulation # чистые детерминированные правила и переходы состояния
packages/content    # Zod-схемы, загрузчики, нормализация, content digest
packages/presentation # read models и localization projections
packages/application  # commands, session lifecycle, use cases
tools/scenario-runner # headless-исполнение, parity, benchmarks
tests/architecture, tests/e2e
migration/oracle/v1   # неизменяемый корпус поведения C#
```

Направление зависимостей: `simulation ← content ← application ← apps/web`; `simulation ← presentation ← application`; `apps/desktop` общается с приложением только через `DesktopApi`. Pixi-фасад живёт в `apps/web/src/world`, типизированный desktop API — в `apps/desktop/src/preload`.

Отдельные пакеты `protocol`, `testkit` и `render-pixi` **не создаются**. У них сегодня нет независимых потребителей, а раннее дробление добавило бы границы, которые пришлось бы поддерживать без выгоды. Их появление требует измеренной потребности и поправки к этой записи.

`dependency-cruiser` — единственная авторитетная механическая проверка направления зависимостей и отсутствия циклов. Второй boundary-линтер не вводится: два расходящихся источника архитектурных правил хуже одного.

### Гейт Electron/Steam проходится до переписывания симуляции

> **Сужено [`ADR-011`](ADR-011-electron-gate-without-steam.md) (2026-08-16).** Игра делается как desktop-приложение прежде всего для владельца; поставки через магазин в области миграции нет. Task 4 проверяет packaged Electron и границу безопасности renderer, `steamworks.js` и App ID `480` из него изъяты, Steam-часть Task 17 не выполняется. Всё остальное в этом разделе — обязательность гейта, порядок «до переписывания правил», условия провала по Electron — действует.

Packaged Windows Electron + `steamworks.js` в main process проверяются **до** начала переноса правил (Task 4 плана миграции, Phase 0.5 решения о стеке). Гейт обязателен: Task 6 не начинается, пока он не зелёный. Календарная дата 2026-08-31 — точка обязательного ревью владельца, а не автоматический технический провал.

Матрица доказательств из двух обязательных строк:

- локальный Windows-прогон с запущенным Steam-клиентом и App ID `480` (Spacewar): загрузка native module, `SteamAPI_Init`, identity, применимость overlay;
- CI/offline packaged-прогон без Steam: корректная деградация и нормальный старт игры.

Spacewar **не** доказывает собственные достижения, схему статистики, квоты Cloud и конфигурацию depot — они повторяются с реальным App ID в Task 17.

**Условия остановки гейта.** Гейт провален, и миграция останавливается, если обязательные Steam-возможности требуют `--no-sandbox`, `--single-process`, `--in-process-gpu`, отключения `contextIsolation` или включения Node integration в renderer; либо если packaged Windows-сборка не может загрузить native module и выполнить `SteamAPI_Init` при сохранённых настройках безопасности после трёх focused work days. Неработающий overlay этим условием не является.

### Sandbox обязателен, overlay — best-effort

`sandbox: true`, `contextIsolation: true`, `nodeIntegration: false`, CSP, allowlist IPC-методов и валидация всех IPC-payload через Zod являются обязательной границей безопасности. Рекомендация README `steamworks.js` включить `nodeIntegration` и отключить `contextIsolation` **не применяется**.

Steam overlay считается best-effort: если он требует ослабляющих process/security model флагов, overlay отключается, результат записывается как `unsupported` и в Definition of Done миграции не входит. Достижения, статистика и Cloud оцениваются независимо от overlay.

Собственный Electron `autoUpdater` не используется: сборки доставляет Steam. Сроки по advisory сохраняются, основание про Steam — нет: [`ADR-011`](ADR-011-electron-gate-without-steam.md) убрал магазин из области, и обновление локальной сборки это пересборка. Security advisory оценивается не позднее 7 дней после публикации, critical runtime fix собирается и выкладывается не позднее 14 дней.

### Область миграции — Windows 10/11 x64 и Chromium browser build

Migration Definition of Done ограничен браузерной сборкой в pinned Chromium и Windows 10/11 x64 Electron package. Native macOS, native Linux и Steam Deck/Proton **не обещаются** этой записью: native module, подпись и Deck требуют отдельных pipelines. Их поддержка принимается отдельной записью после Windows cutover и снятых измерений.

Численные границы, блокирующие cutover: ~~установленный Windows-пакет ≤ 300 МБ~~ — порог отменён [`ADR-011`](ADR-011-electron-gate-without-steam.md) по замеру Task 4 (304,2 МиБ на пустом приложении с урезанными локалями), размер продолжает сниматься без порога; суммарный RSS корневого процесса Electron и всех его renderer/GPU/utility-потомков на normal contract-offer screen после прогрева ≤ 500 МБ.

### Неизменяемый oracle corpus переживает удаление C#

До переноса правил наблюдаемое поведение текущей C#-реализации материализуется как **данные** в `migration/oracle/v1/`: RNG-векторы, векторы канонизации, а для каждого manifest/checkpoint — входы, исход и код ошибки, финальное состояние, результаты шагов, события, причинные следы, presentation read model, канонические байты и хеш. Каждый файл корпуса покрыт SHA-256 в `manifest.json`; изменение байта требует шага версии артефакта и записанной причины.

Корпус остаётся в дереве **после** удаления C# и продолжает исполняться TypeScript-тестами. Git history остаётся дополнительным историческим источником, но не единственным oracle: восстанавливать поведение из удалённого кода — не проверка, а археология.

### Записанный fallback

Единственный предварительно одобренный fallback — **текущая C#-симуляция за TypeScript/web-презентацией**. Он рассматривается, если Task 9 (перенос правила решения героя и движка симуляции) не достигает семантического parity в пределах стоп-гейта: 10 focused work days на Tasks 7–10 или 2026-09-20, что наступит раньше.

Это не автоматическое решение. Оно требует записанных измеренных причин расхождения и новой принятой записи до реализации. Возврат продуктовых фич в Godot и молчаливое сокращение migration DoD допустимым способом уложиться в срок не являются.

## Альтернативы

- **Остаться на Godot 4 + C#** — отклонено: цена runtime/UI verification повторяется на каждом новом состоянии экрана, а движок даёт продукту physics, navigation и editor-authored scenes, которыми он не пользуется. Дешевле в ближайшую неделю, дороже на горизонте разработки.
- **C# без Godot, Avalonia host** — минимальный по объёму rewrite: симуляция, adapters и большая часть тестов сохранились бы, переписывался бы только UI/runtime. Отклонено как итоговый вариант: информационный UI стал бы удобнее, но проект не получил бы browser-first delivery, DOM/accessibility tree и основной Playwright workflow — то есть ровно те причины, ради которых миграция затевается.
- **C# core + web UI** — сохраняет проверенное ядро и даёт React/DOM. Отклонено как production-архитектура: два языка, постоянный IPC, два build/test контура и необходимость синхронизировать контракты на каждой игровой фиче. Сохранён как единственный fallback (см. выше).
- **Unity** — отклонено: усиливает неиспользуемые стороны Godot (editor-centric workflow, asset metadata, дорогой runtime loop) и не решает UI-first задачу.
- **Bevy + Rust** — отклонено: новый язык и ECS без доказанной необходимости, худшая пригодность для сложного информационного UI, длинная platform/runtime инфраструктура до проверки продукта.
- **Phaser + TypeScript** — отклонено не по качеству, а по соответствию форме продукта: основная часть интерфейса всё равно строится в React/DOM, Phaser создаёт второй scene lifecycle рядом с application state, а physics и большинство game object systems этому дизайну не нужны.
- **LÖVE / Defold + Lua** — отклонено: сложный информационный UI пришлось бы строить внутри игрового canvas, а Lua ослабляет compile-time contracts, на которые `AGENTS.md` §10 сознательно опирается для параллельной агентской работы.
- **Tauri вместо Electron** — отклонено: добавляет Rust и Cargo, использует разные системные webview на разных ОС, создаёт второй основной E2E path через WebdriverIO и усложняет Steam bridge. Оптимизирует размер bundle, а не скорость агентской разработки.
- **Чистый PWA как единственный runtime** — отклонено как основной Steam host из-за browser storage lifecycle и отсутствия естественной Steamworks integration; сохранён как browser target для плейтестов.
- **Собственный движок** — отклонено: превращает инфраструктуру в отдельный продукт, что противоречит цели ускорить проверку игры.
- **Оставить `ADR-001` действующим и трактовать миграцию как «исправление ошибки»** — отклонено как неверное описание фактов: `ADR-001` решал Gate 0 на доступных тогда данных и решал его обоснованно. Изменились данные, а не качество прежнего рассуждения.

## Последствия

- **Полное переписывание несёт риск семантической регрессии.** Митигируется неизменяемым oracle corpus, differential parity по всем 27 manifests, сравнением полей причинного следа и запретом массового обновления снапшотов.
- **Electron увеличивает размер дистрибутива и baseline-потребление памяти.** Компромисс принят численно: 300 МБ пакета и 500 МБ RSS блокируют cutover при превышении. Порог размера снят [`ADR-011`](ADR-011-electron-gate-without-steam.md): замер Task 4 показал 304,2 МиБ до первого байта игрового контента, то есть граница лежала ниже пола платформы. Действует бюджет RSS.
- **Electron требует регулярных security/runtime обновлений**, а обновить runtime внутри уже поставленной игры он сам не может. Отсюда exact pin, 7 дней на оценку advisory и 14 на critical rebuild.
- **npm увеличивает supply-chain surface.** Отсюда `--frozen-lockfile`, exact direct versions, ревью каждой новой runtime dependency и allowlist install/build scripts.
- **TypeScript не даёт C#-уровень numeric discipline автоматически.** Домен остаётся целочисленным; там, где нужна семантика 64-битного переполнения, используется локальный `bigint`, который никогда не пересекает границу JSON/пакета.
- **`ADR-001` получает статус `superseded` этой записью.** Тело `ADR-001` и Godot-специфичный механизм `ADR-008` переписываются на этапе cutover (Task 19 плана миграции) — вместе с удалением кода, который они описывают, чтобы запись и дерево меняли смысл одним шагом.
- **`ADR-002`, `ADR-003`, `ADR-004`, `ADR-005`, `ADR-007`, `ADR-009` сохраняют намерение.** Заменяется механизм и пути реализации, а не решения: чистая симуляция, counter-based RNG, версионируемый контент, стабильные ID, конверт события и причинный след переносятся как поведение.
- **Продуктовые записи `DEC-001`…`DEC-010` не пересматриваются.** Они не зависят от движка; у них могут обновиться только ссылки на удалённые пути.
- **Feature freeze для старого runtime** действует до 2026-10-11. Исключения: извлечение oracle, дефекты миграции и критические исправления данных. Продление freeze после этой даты требует отдельного решения владельца.
- **Миграция не является редизайном.** Формула решения героя, баланс, product pillars, стабильные коды, семантика контента и канонические артефакты не меняются ради зелёного parity. Любое наблюдаемое изменение поведения требует отдельной записи `DEC`, любая смена границы движка/языка/платформы — `ADR`.

## Проверка

Решение работает, если одновременно верно всё перечисленное (полный список — Migration Definition of Done в плане миграции и [`FULL_TYPESCRIPT_MIGRATION`](../production/FULL_TYPESCRIPT_MIGRATION.md)):

- все 27 scenario manifests и их checkpoints совпадают с неизменяемым корпусом `migration/oracle/v1`;
- RNG-векторы, порядок событий и следов, стабильные коды и канонические артефакты совпадают при объявленных версиях артефакта;
- `dependency-cruiser` доказывает направление зависимостей и отсутствие циклов;
- симуляция не зависит от DOM, React, PixiJS, Electron, файловой системы, часов и глобальной случайности;
- пять состояний экрана реализованы с семантическими assertions и достижимостью при 1280×800;
- ~~packaged Windows x64 build инициализирует Steam в main process и работает без Steam при сохранённом sandbox~~ — изъято [`ADR-011`](ADR-011-electron-gate-without-steam.md); действующее требование: packaged Windows x64 build запускается при сохранённых `sandbox: true`, `contextIsolation: true`, `nodeIntegration: false` и CSP;
- RSS ≤ 500 МБ по зафиксированной методике; размер установленного пакета снимается тем же прогоном и записывается без порога ([`ADR-011`](ADR-011-electron-gate-without-steam.md));
- в production tree не остаётся `.cs`, `.csproj`, `.sln`, `.tscn`, `.uid`, `project.godot`, пинов Godot/.NET SDK и Godot-специфичного harness;
- `migration/oracle/v1` остаётся в дереве и проходит проверку дайджестов **после** удаления старого кода.

Каждое число приводится вместе с командой, которой оно снято, и ссылкой на артефакт прогона (`AGENTS.md` §11). Измеренные итоги, статус overlay, поддержанная область и дайджест корпуса дописываются сюда датированной заметкой о завершении реализации на Task 20; статус `accepted` при этом на `superseded` не меняется.
