# ADR-012 — Тексты интерфейса живут вне `content/`, в каталоге `ui-text/`

> Дата: 2026-08-19
>
> Статус: accepted (решение владельца, 2026-08-19)

## Контекст

`AGENTS.md` §6 требует двух вещей сразу: «игровые тексты локализуемы и не являются
ключами логики» и «данные живут в `content/`». Пока каталог локали был один, эти два
требования складывались в одно правило, которое сегмент 5 и унаследовал в своих общих
ограничениях: «Новый ключ идёт в `content/locale/ru.json` и под проверку полноты в
`tests/locale`».

Правило перестало быть исполнимым, и это замер, а не рассуждение.

`content_version` — дайджест по **всему** дереву `content/`, включая
`content/locale/ru.json` (`ADR-004`). Замороженный корпус `migration/oracle/v1` пиннит
это число во всех 54 записях: `5d03734fd9c7abaa`. Проверяется командой:

```bash
pnpm scenario:parity
```

На нетронутом дереве:

```
entries:     54/54 reproduced
```

После добавления **одного корректного ключа** внутрь `entries` каталога
`content/locale/ru.json`:

```
first structural difference: $.content_version: "e036d5cbb35bc29d"
                             where the corpus has "5d03734fd9c7abaa"
content_version is e036d5cbb35bc29d, corpus has 5d03734fd9c7abaa
[ELIFECYCLE] Command failed with exit code 1.
```

Сам прогон при этом отрабатывает нормально: ломается не игра, а сверка с замороженным
числом. То есть **пока корпус остаётся оракулом, в `content/` нельзя добавить ни одной
новой строки текста**. Это блокировало ключи девяти кодов отказа сохранения
(`SaveErrorCodes`, Task 16.4) и весь экран слотов (Task 16.8) — работу, которая к текстам
контента отношения не имеет вовсе.

Пересобрать корпус нельзя: он — единственное свидетельство, по которому измеряется вся
миграция, и он обязан оставаться сравнимым с C#-стеком, который ещё в дереве
(`FULL_TYPESCRIPT_MIGRATION`, Task 19 — cutover).

## Решение

### Два каталога, граница по природе ключа

Тексты, которые порождает **интерфейс**, а не контент, живут в каталоге вне `content/`,
которого дайджест не видит:

```
ui-text/ru.json      { "schema_version": 1, "locale": "ru", "entries": { … } }
```

Что куда:

- **`content/locale/ru.json`** — ключ описывает игровые *данные*: имя героя, название
  контракта, название черты, тег. Такой ключ обязан входить в `content_version`, потому
  что он часть того, чем контент является: переименование героя — изменение контента, и
  версия контента обязана это отразить.
- **`ui-text/ru.json`** — ключ придуман интерфейсом: код отказа, подпись слота, кнопка,
  заголовок экрана. Он не описывает никаких данных и не должен двигать версию контента:
  сегодня это девять ключей `SaveErrorCodes`, дальше — экран сохранений.

Каталог читается **тем же способом**, что контент: через `ContentFileSource`
(`loadUiTextCatalogue` в `packages/content/src/ui-text/`), с той же строгой разборкой
JSON, тем же потолком размера, тем же запретом повторного ключа и тем же шаблоном ключа
`LOCALIZATION_KEY_PATTERN`. Один читатель на оба формата — по тому же основанию, по
которому `FULL_TYPESCRIPT_MIGRATION` §12.2 отверг сериализацию контента на этапе сборки:
два пути, обязанных согласовываться, и ничего, что бы их к этому принуждало, — уже
оплаченный этим репозиторием класс дефектов.

Что модуль лежит под `packages/content/`, к границе отношения не имеет: дайджест
считается по дереву данных `content/`, а не по пакету, который его читает.

Собственная версия схемы — `1`, а не `2` каталога контента. Форматы меняются по разным
причинам: один следует авторингу контента, другой — экранам, и общий номер связал бы
следующее изменение любого из них с другим.

### Граница действует вперёд; назад действует «что уже там, то там»

Это цена, а не деталь, и она называется прямо.

`content/locale/ru.json` **уже содержит** ключи, которые по границе выше принадлежат
интерфейсу: `screen.contract_offer.title`, ключи `action.*`, `error.*` пяти кодов
`ERROR_CODES`, `reason.*`, `response.wavered.*`. Перенести их нельзя: перенос меняет
`content_version` ровно так же, как добавление, и красит те же 54 записи. Поэтому на
время миграции действует правило из трёх строк:

- **старый каталог заморожен** — ни одного нового ключа, ни одного перенесённого;
- **всякий новый ключ идёт в `ui-text/`** — по природе ключа;
- **существующие интерфейсные ключи остаются на «неправильной» стороне до Task 19**, где
  корпус перестаёт быть оракулом; там перенос делается одной правкой.

То есть примерно тридцать ключей в `content/locale/ru.json` сегодня лежат не там, где
велит правило, и правило этого не скрывает.

### Названное исключение из `AGENTS.md` §6

Строка «данные живут в `content/`» получает исключение с владельцем и сроком:

- **исключение:** тексты, порождаемые интерфейсом, живут в `ui-text/`, а не в `content/`;
- **владелец:** владелец проекта (это решение);
- **срок:** до Task 19 (cutover), где корпус перестаёт быть оракулом. Тогда пересматривается
  вопрос, остаются ли каталога два или они сливаются обратно в один.

Это **второе** исключение из строки, а не первое: первым был `Theme` UI-kit.
**Третьего не заводится:** по `AGENTS.md` §12 п. 3 («исключения не накапливаются») третий
случай переписывает правило целиком, а не добавляет к нему оговорку.

`AGENTS.md` §12 п. 2 замораживает число процессных документов; реестр решений процессным
документом не является (там же, прямым текстом), а правка §6 — изменение существующего
файла, а не новый. Ни то, ни другое правилу не противоречит.

Строка §6 приведена в соответствие вместе с принятием этой записи: до неё она читалась
«Единственное исключение — `Theme` UI-kit», что после второго исключения перестало быть
правдой. Пункт переписан целиком, а не дополнен оговоркой снизу, — этого требует §12 п. 5.
Правку санкционировал владелец 2026-08-19, отдельным решением: `AGENTS.md` определяет, чего
исполнитель не решает сам, поэтому его текст не правится по рассуждению исполнителя даже
тогда, когда рассуждение верное.

### Что это проверяет

Проверка полноты в `tests/locale/catalogue.test.ts` переписана с одного каталога на два:

1. каждый ключ, который умеет произвести presentation **или** application, существует
   **ровно в одном** из двух каталогов;
2. **ни один ключ не лежит в обоих** — два объявления одного текста по разные стороны
   границы иначе разъедутся молча; это ровно та форма, которой сегмент 4 закрыл
   `KNOWN_SCREEN_STATES` против `SCREEN_STATES`;
3. каталог контента не пополнялся: число ключей в нём (94) и `content_version`
   (`5d03734fd9c7abaa`) — утверждение, а не наблюдение, и краснеет в `pnpm test`, то есть
   раньше и внятнее, чем 54 упавшие записи `pnpm scenario:parity`.

## Альтернативы

- **Пересобрать корпус после каждого нового ключа.** Отклонено: корпус — единственное
  свидетельство, по которому измеряется миграция, и «оракул, который переписывают, когда
  он мешает» оракулом не является. Он же обязан оставаться сравнимым с C#-стеком, пока тот
  в дереве.
- **Исключить `locale/` из дайджеста контента.** Отклонено: это меняет `content_version`
  для всего дерева разом (то же самое падение 54 записей), а заодно снимает защиту с имён
  героев и названий контрактов, которые версией контента покрываться обязаны.
- **Держать тексты интерфейса в коде — константами или литералами в компонентах.**
  Отклонено: `AGENTS.md` §6 и `TDD` §11.1 запрещают собранную в коде player-facing строку,
  и запрет стоит не на форме хранения, а на том, что такую строку нельзя перевести и
  нечем проверить на полноту.
- **Отложить коды отказа до Task 19.** Отклонено: тогда экран сохранений либо показывает
  игроку `SAVE_CHECKSUM_MISMATCH`, либо не показывает ничего, и вся ветка отказов
  сохранения остаётся непроверяемой до конца миграции.
- **Завести отдельный пакет `packages/ui-text` под загрузчик.** Отклонено: загрузчику
  нужны `ContentFileSource`, строгий читатель JSON и шаблон ключа — всё это уже живёт в
  `packages/content`, и новый член workspace добавил бы манифест, tsconfig, запись в
  `lint:deps` и ещё одну границу ради восьмидесяти строк.

## Последствия

- **Каталогов два, и резолвер текста обязан знать про оба.** Каждый потребитель ищет ключ
  сначала в одном, потом в другом; пункт 2 проверки выше — то, что делает порядок поиска
  неважным, а не соглашение о нём.
- **Граница не самопроверяема по природе ключа.** Ничто механически не скажет, что
  `screen.saves.title` — интерфейсный, а `hero.core.bram.name` — контентный: это суждение
  автора. Механически проверяется другое и более важное — что каталог контента не растёт
  вовсе (пункт 3), а значит любой новый ключ физически может оказаться только в `ui-text/`.
- **Около тридцати интерфейсных ключей лежат не на своей стороне** и будут лежать до
  Task 19. Это делает границу правилом «вперёд», а не описанием текущего дерева, и читателю
  кода она сама себя не объяснит — объясняет эта запись.
- **`pnpm scenario:parity` перестаёт быть единственным сторожем `content/`.** Правка внутри
  дерева контента теперь краснеет в `pnpm test` одной строкой, которая называет причину.
- **Бандлеру приходится знать про второй корень.** `apps/web/src/content-source.ts` глобил
  `content/**` и `scenarios/**`; каталог интерфейса — единственное дерево, которое игра
  читает и которое шаблон по `content/` покрыть не может **по построению**. Поэтому он
  добавлен в глоб сразу, а не вместе с первым экраном-потребителем: без строки в глобе
  файла в бандле нет, падение приходит в рантайме браузера, а `pnpm test`, `pnpm lint:deps`
  и `pnpm scenario:parity` остаются зелёными. Проверено тестом «браузерный источник отдаёт
  то же, что node-загрузчик» — форма `source-agreement.test.ts`.
- **Замороженный хеш `5d03734fd9c7abaa` записан в дереве дважды:** как
  `RECORDED_CONTENT_VERSION` в `packages/content/src/source-agreement.test.ts` (два
  источника отвечают одно) и как `FROZEN_CONTENT_VERSION` в
  `tests/locale/catalogue.test.ts` (в `content/` ничего не добавлялось). Утверждения
  разные, поэтому константа не общая; файлы ссылаются друг на друга комментариями.
  **Task 19 снимает оба**, а не только второй.
- **Task 19 получает конкретную работу, а не пожелание:** слить каталоги обратно или
  оставить два, перенести существующие интерфейсные ключи, снять оба пина хеша и
  пересобрать корпус — одной правкой, когда корпус перестаёт быть оракулом.
- **Обратное направление проверяется с Task 16.8.** Каталог контента от мусора защищён
  заморозкой, а новый был не защищён ничем: ключ, который никто не порождает, лежал бы в
  `ui-text/ru.json` и переводился бы впустую. Симметричное утверждение появилось вместе с
  экраном слотов, когда каталог вырос с девяти ключей до тридцати трёх — `tests/locale`
  требует, чтобы множество ключей файла **совпадало** с тем, что производят слои, а не
  включало его. Цена названа честно: ключ, добавленный за шаг до своего потребителя,
  краснеет — и это ровно то, что нужно, потому что «шаг» здесь измеряется коммитами, а
  между ними ключ уже проверен и переведён.

## Проверка

Решение работает, если одновременно верно:

- `pnpm scenario:parity` отвечает `entries: 54/54 reproduced` — то есть `ui-text/` находится
  вне того, что видит дайджест;
- `ui-text/**/*.json` покрыт `.gitattributes` правилом `text eol=lf`: без него свежий клон
  на Windows красит `pnpm format:check` на файле, который никто не редактировал, при
  зелёном `ubuntu-latest` на том же коммите;
- браузерный источник отдаёт для `ui-text/ru.json` ровно то же, что node-загрузчик;
- `tests/locale/catalogue.test.ts` зелёный на всех трёх утверждениях выше и краснеет на
  каждом из трёх мутантов: новый ключ в `content/locale/ru.json`; один ключ, объявленный в
  обоих каталогах; удалённый ключ кода отказа;
- `content/locale/ru.json` содержит 94 ключа и ни одним больше, пока действует эта запись;
- ни одна player-facing строка не собрана в коде.

Пересматривается на Task 19 (cutover), когда корпус перестаёт быть оракулом: тогда
`content_version` можно двигать, перенос существующих интерфейсных ключей стоит одной
правки, и вопрос «два каталога или один» решается заново — уже без давления замороженного
числа.
