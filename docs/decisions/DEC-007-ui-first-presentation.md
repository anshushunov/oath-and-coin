# DEC-007 — UI-first презентация и схематичный бой до валидации MVP

> Дата: 2026-08-12
>
> Статус: accepted

## Контекст

Частично закрывает вопрос Q-18 GDD. Игра — менеджер в духе Football Manager: игрок живёт в экранах данных, а бой — проверка подготовки. Одновременно арт — худшая дорожка для агентской разработки: дорогая, плохо параллелится и не проверяется автоматически. Опыт Dungeon Fortress показал, что арт-пайплайн требует отдельной инфраструктуры, которая не должна блокировать проверку игровых гипотез.

## Решение

- Презентация MVP — информационный UI и схематичный 2D-бой: токены, полоски состояния, иконки намерений, текстовые причины.
- Никакого целевого арта (иллюстрации, анимации, диорамы) до успешной валидации External MVP.
- Читаемость боя достигается информационным дизайном (намерения, лог, пауза, trace), а не анимацией.
- Выбор финальной камеры боя (Q-18: диорама / 2D side / изометрия) откладывается до подготовки Vertical Slice и не блокирует ни один milestone до M4.

## Альтернативы

- Ранний целевой арт — отклонено: замедляет итерации, не проверяет ни одну гипотезу из плана валидации.
- Чисто текстовая игра без визуализации боя — отклонено: автобой без пространственного представления не проверяет читаемость (H3, P5).

## Последствия

- Milestone 1–3 полностью реализуемы агентами без художника.
- Экраны из GDD §16.2 проектируются как данные + компоненты, пригодные для генерации.
- Риск: схематичная картинка занижает восприятие качества у внешних тестеров; смягчение — аккуратная типографика и единый UI-kit.

## Проверка

Exit criteria M2: тестеры объясняют исход боя по схематичному представлению. Пересмотр — после External MVP при планировании Content Complete.
